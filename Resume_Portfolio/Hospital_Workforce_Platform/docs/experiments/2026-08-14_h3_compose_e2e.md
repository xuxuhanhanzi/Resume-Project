# 实验记录：H3 Docker Compose 全链路

## 1. 目标

用生产构建产物启动 MySQL、Redis、Keycloak、backend、frontend、Prometheus 与 Grafana，
通过真实 OIDC token 验证健康检查、权限矩阵、幂等排班、冲突拒绝、审计与监控采集。

## 2. 最终拓扑与版本

- backend：Java 21 / Spring Boot 3.5.3 生产镜像；
- frontend：Node 22 构建、Nginx 1.27 Alpine 托管静态产物；
- MySQL 8.4、Redis 7.4 Alpine、Keycloak 26.1.4；
- Prometheus 3.2.1、Grafana 11.5.2；
- Docker Desktop 4.82.0 / Engine 29.6.1 / API 1.55。

## 3. 可复现命令

```powershell
Copy-Item .env.example .env
docker compose up --build -d
.\scripts\demo.ps1
```

脚本不打印 access token，会等待各服务就绪并在失败时以非零状态退出。

## 6. 保留的异常与修复

- Docker 内 `npm ci` 多次出现 `ECONNRESET`：为整条安装命令设置最多 5 次有限重试，复用
  BuildKit cache，并使用 host build network；独立生产构建最终通过。
- 生产后端镜像曾解析 Testcontainers 测试依赖失败：把测试依赖放入默认激活的 Maven
  `tests` profile，生产构建显式 `-P!tests -Dmaven.test.skip=true`，保持生产边界干净。
- 首次真实 API 调用暴露 Redis `Cannot serialize`：让 `Department` 实现 `Serializable`，
  并增加缓存序列化回归测试；完整测试现为 7/7。
- Grafana 挂载整个 provisioning 目录时报告缺少子目录：改为只读挂载明确的数据源文件。

## 7. 结论

H3 全链路通过。结论限定于本机 Docker Compose 环境；未将开发账号、默认密码或
`start-dev` Keycloak 配置描述为生产部署方案。
