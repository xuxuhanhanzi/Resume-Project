# ADR-0001：以模块化单体作为初始架构

- 状态：Accepted
- 日期：2026-08-14

## 背景

组织、人事、排班和薪资之间存在需要强一致事务保护的写路径。项目规模与团队规模均不足以
证明独立服务、分布式事务和跨服务运维成本是合理的。

## 决策

使用一个 Java 21 / Spring Boot 部署单元，通过业务包与 Spring Modulith 测试保持模块边界。
模块间使用应用服务或领域事件协作；MySQL 是事务事实来源，Redis 只承担可丢失、可重建缓存。

## 后果

- 优点：本地单事务即可保护排班与工资单一致性；部署和调试成本较低；模块依赖可自动验证。
- 代价：所有模块共享进程和发布节奏；热点模块不能单独水平扩缩。
- 演进条件：只有在监控显示独立扩缩需求、团队所有权分离或发布耦合成为实际瓶颈时，才拆出
  边界清晰的模块。拆分前需要先引入 outbox 与可观测的异步契约。

## 被否决方案

- 初始即拆分微服务：当前没有流量或组织证据支撑其复杂度。
- 按技术层分包：会让领域规则跨 Controller/Service/Repository 扩散，难以验证依赖方向。
