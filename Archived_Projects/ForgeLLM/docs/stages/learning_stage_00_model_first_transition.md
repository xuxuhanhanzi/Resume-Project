# 学习 Stage 0：切换到模型优先路线

> 制定日期：2026-07-24（Asia/Singapore）  
> 性质：学习路线与项目门禁重构，不新增模型功能  
> 预计时间：0.5 周以内  
> 费用预算：0 USD

## 1. 阶段目标

在不删除既有工程与数据实现的前提下，取消 Day 4–14 的逐日学习前置门槛，把 ForgeLLM 的主要学习时间重新集中到 Tokenizer、PyTorch 模型构造、预训练、自定义 C++/CUDA 算子、后训练与模型评测。

## 2. 假设

Day 1–3 已经提供继续开发所需的最低工程认知。只要当前质量门仍然通过，并为工程/数据支撑知识保留按需查阅入口，就可以停止全量工程复盘并直接进入 Tokenizer，而不会破坏后续模型实验的正确性与可追踪性。

若学习者无法运行项目质量命令、无法定位配置/测试入口，或路线重构导致后续模型任务缺少必要的测试与实验记录，则该假设失败，按具体缺口补学，而不是恢复整个 14 天课程。

## 3. 唯一主变量

学习与验收制度从“Day 1–14 全量工程/数据课程全部通过后才能继续”，改为“核心算法完整学习，支撑知识按任务即时补充”。

## 4. 固定项

- 保留现有源码、测试、数据夹具、实验记录与历史学习文档；
- 不降低模型正确性、数据隔离、Checkpoint/Resume 和评测门槛；
- 不在 Stage 0 实现 Tokenizer、Transformer、训练循环或后训练；
- 不启动付费任务或下载大规模数据；
- 本地仍使用仓库 `.venv` 和权威质量入口；
- 所有尚未实际完成的模型能力继续标记为未开始。

## 5. 对比对象

- 旧基线曾要求 Day 1–14 逐日学习与最终复盘；相关过时计划已在当前路线稳定后删除；
- 新方案：核心知识使用完整讲义和阶段项目，工程/数据支撑知识使用执行卡并按需扩展。

## 6. 指标与成功门槛

| 指标 | 成功门槛 |
|---|---|
| 计划唯一性 | README 与状态文档只把模型优先 21 周计划列为当前主路线 |
| 历史兼容 | 路线切换时先标记旧计划；当前路线稳定后已删除会干扰学习顺序的过时计划，Stage 0 证据继续保留 |

## 7. 失败处理

- 质量门失败：定位并记录失败；只修复与本次文档调整相关的问题，既有代码问题另行登记；
- 文档出现冲突：以 `docs/model_first_21_week_learning_plan.md` 为唯一当前主计划；会形成第二学习入口的过时计划在审计后删除；
- 后续任务暴露知识缺口：使用执行卡定位到旧讲义或源码，进行 30–120 分钟定向补学；
- Tokenizer 启动条件不足：只补数据来源、切分隔离或存储等具体缺口，不恢复全量工程课程。
