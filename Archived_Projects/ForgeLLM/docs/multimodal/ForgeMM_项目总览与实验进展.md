# ForgeMM 项目总览与实验进展

> 更新日期：2026-08-06  
> 当前阶段：多模态后训练基线与可信评测已经形成闭环；视觉证据选择创新模块尚未实现。  
> 文档用途：统一说明项目为什么存在、正在解决什么问题、使用哪些模型与技术、已经完成哪些实验，以及下一步如何推进。

## 1. 项目定位

ForgeMM 是 ForgeLLM 的多模态扩展项目。它不是从零训练一个新的视觉语言大模型，也不调用商业闭源 API，而是在本地开源视觉语言模型上研究：如何在消费级显卡和有限训练数据条件下，进行可解释、可复现的多模态微调与评测。

当前项目以图表问答为任务入口。模型接收一张图表和一个自然语言问题，输出简短答案。例如：读取某一年的数值、比较两个类别、计算平均值或总和。

项目同时服务两个目标：

1. **学习目标**：理解视觉语言模型的数据流、视觉 Token、跨模态对齐、SFT、LoRA/QLoRA、数据审计和可信评测，而不把主要精力消耗在非关键工程细节上。
2. **项目目标**：形成一套可提交到 GitHub、可以复现实验、能够用于简历说明的完整多模态后训练系统。

## 2. 项目要解决的问题

图表问答并不只是普通文本问答。模型需要连续完成：

```text
图像编码
→ 识别标题、坐标轴、图例和数值
→ 找到与问题有关的视觉证据
→ 完成比较或算术推理
→ 生成符合格式的短答案
```

现成视觉语言模型已经具备一定图表理解能力，但直接进行小数据微调存在三个问题：

- 微调可能只记住答案格式，并没有增强视觉读取或数值推理能力；
- LoRA 覆盖模块过多或学习率过高，可能破坏底座原本正确的能力；
- 小而有偏的验证集可能让几个样本决定模型排名，产生虚假的“提升”或“退化”。

因此，当前首先解决的工程研究问题是：

> 在固定开源 VLM、有限数据和 8 GB 显存条件下，怎样建立一个数据可信、变量受控、能够判断微调究竟改进还是破坏模型的多模态后训练基线？

在基线稳定后，项目的长期研究问题是：

> 在固定视觉 Token 预算下，问题条件的图表区域或视觉 Token 选择，能否同时改善答案准确率、证据定位质量与推理成本？

长期方向暂定为 **ForgeMM-ChartEvidence**。当前完成的 QLoRA 与评测工作是它的实验地基，不代表 query-conditioned region/token selector 已经实现。

## 3. 当前范围与明确边界

### 3.1 当前正在做

- 图像与文本输入的 ChartQA 图表问答；
- Qwen2.5-VL-3B-Instruct 的本地推理和参数高效微调；
- Answer-only SFT；
- 不同语言侧 LoRA 模块范围与学习率的单变量对照；
- 数据完整性、重复和分布偏差审计；
- 固定清单上的严格评测、宽松评测和逐样本迁移分析；
- 可恢复训练、Adapter 保存、配置与哈希留档。

### 3.2 当前没有做

- 从零预训练 Qwen2.5-VL-3B；
- 单独训练图像、文本或音频 Embedding 模型；
- 修改 Transformer、FFN、视觉编码器等基础架构；
- 音频、视频、多页文档或 GUI Agent；
- DPO、GRPO、RLVR、RAG、MCP 或 Agent 工作流；
- 面向公众的在线部署；
- 已经实现视觉证据选择或视觉 Token 剪枝。

这些技术并不是永久排除，而是当前不能同时引入。必须先让监督微调和固定评测成为可靠基线，再逐项加入新的研究变量。

## 4. 使用的模型

### 4.1 主模型

项目当前使用：

**Qwen2.5-VL-3B-Instruct**

- 类型：开源预训练视觉语言模型；
- 使用方式：模型权重下载到本地，不依赖商业 API；
- 本地路径：`D:\Users\27475\Desktop\models\Qwen2.5-VL-3B-Instruct`；
- 当前输入模态：图像 + 文本；
- 当前输出模态：文本短答案；
- 当前硬件：RTX 4070 Laptop GPU，8 GB 显存。

我们使用的是阿里 Qwen 团队已经完成预训练和指令后训练的模型，不是自己从随机参数开始训练。项目训练的是附加在底座上的 LoRA Adapter。

### 4.2 与项目有关的模型结构

根据本地模型配置：

- 语言模型共有 36 层，隐藏维度 2,048，16 个注意力头和 2 个 KV 头；
- FFN 中间维度为 11,008，激活函数为 SiLU；
- 视觉编码器共有 32 层，隐藏维度 1,280，图像 patch size 为 14；
- 视觉特征经过空间合并后映射到语言模型的 2,048 维表示；
- 使用多模态 RoPE，使文本和视觉位置能够进入统一的自回归生成过程。

对本项目最重要的理解是：Qwen2.5-VL 已经完成视觉编码和跨模态对齐。我们不需要重新训练一个“图片转 Token”的独立 Embedding 模型，而是通过统一 Processor 使用模型已有的视觉编码器、视觉合并模块、Tokenizer 和语言模型。

### 4.3 模型在 QLoRA 中如何训练

```text
冻结的 4-bit Qwen2.5-VL 底座
             +
可训练的高精度 LoRA Adapter
             ↓
只用答案 Token 的交叉熵更新 Adapter
```

QLoRA 的 4-bit 主要指冻结底座权重的存储形式，不是把 LoRA 参数或所有计算都变成 4-bit。当前 Adapter 可独立保存和重新加载，不需要复制一份完整 3B 模型权重。

## 6. 当前采用的核心技术

### 6.1 多模态输入与生成

- Qwen2.5-VL 官方 Chat Template；
- 图像与问题联合编码；
- 图像最大像素预算 401,408；
- 贪心解码；
- 最多生成 32 个新 Token；
- 只返回最终短答案，不要求模型输出解释过程。

### 6.2 Answer-only SFT

训练样本仍包含图片、问题、角色模板和答案，但 loss 只计算答案区域：

```text
图像 Token：-100，不监督
用户问题：  -100，不监督
模板 Token：-100，不监督
答案 Token：真实 label，参与交叉熵
```

这仍然是标准 SFT。Answer-only 描述的是监督区域，而 QLoRA 描述的是参数更新和内存策略，两者可以同时使用。

### 6.3 LoRA 与 QLoRA

共同配置：

- NF4 4-bit 冻结底座；
- FP16 compute；
- LoRA rank 8；
- alpha 16；
- dropout 0；
- AdamW；
- 5 步 warmup + cosine decay；
- 50 个优化步；
- 梯度累积 4；
- 每次正式训练实际处理 200 条不同样本。

目前实现了两个 LoRA 范围：

1. 语言注意力：`q_proj/k_proj/v_proj/o_proj`；
2. 语言注意力 + FFN：再加入 `gate_proj/up_proj/down_proj`。

项目使用完整模块路径正则，防止 `gate_proj` 等短名称误命中视觉编码器中的同名模块。

### 6.4 可复现训练

- 固定随机种子和样本顺序；
- 保存 Adapter、优化器、学习率调度器、训练步数和随机状态；
- 验证连续训练与“保存后恢复”得到完全相同的 loss 和 Adapter 哈希；
- 训练前后检查所有非 LoRA 参数没有梯度；
- 检查每个目标 LoRA-B 张量确实发生更新；
- 失败实验和修复记录保留，不用新结果覆盖旧证据。

### 6.5 可信评测

项目同时报告：

- **归一化严格准确率**：当前主指标；
- **ChartQA 数值宽松准确率**：数值答案允许 5% 相对误差，用于兼容常见 ChartQA 协议；
- 按任务类型和答案类型的分类结果；
- 相对原始模型的“改对、改错、保持正确、保持错误”；
- 配对 sign test，避免只看百分点差异；
- 平均答案长度、评测时间与显存等工程指标。

评测器使用固定 CSV manifest。每个预测逐条追加并刷新到 JSONL；断点恢复时会验证现有记录必须是当前 manifest 的严格前缀，避免误用不同数据继续运行。

## 7. 已完成的实验

### 7.1 基线冒烟

原始 Qwen2.5-VL-3B-Instruct 在 20 条 ChartQA human validation 样本上完成本地端到端验证：

- 严格准确率：45.0%；
- 宽松准确率：50.0%；
- 峰值已分配显存：约 2.54 GiB。

该实验只证明模型、图片、量化与评测链路可运行，不作为最终基准成绩。

### 7.2 第一轮 QLoRA 对照

| 实验 | 唯一主变量 | 可训练参数 | val50 严格准确率 | 当时结论 |
|---|---|---:|---:|---|
| 原始模型 | 无 Adapter | 0 | 46% | 冻结基线 |
| B1 | Attention QLoRA，LR `2e-4` | 3,686,400 | 42% | 工程闭环通过，但小验证集上退化 |
| B2 | Attention + FFN QLoRA，LR `2e-4` | 14,966,784 | 40% | 参数扩大约 4 倍，没有得到收益 |
| B3 | Attention QLoRA，LR `5e-5` | 3,686,400 | 44% | 降低学习率减少破坏，但仍低于 val50 原模型 |

这轮实验说明：训练 loss 下降不等于泛化能力提升；扩大 LoRA 模块范围也不自动带来更好结果。不过 val50 本身存在偏差，因此这些排名只能作为数据诊断的触发信号。

### 7.3 数据审计

数据审计完成了全量 human/augmented 结构检查、图片哈希泄漏检查、任务/答案分布分析和分层清单生成。

重要结果：原来的前 50 条验证集不是完整 val human 的可靠近似，因此 B1–B3 必须在更大的同一清洁验证清单上重新评估。

### 7.4 清洁分层 val250 四模型复评

四个模型使用同一模型底座、同一 4-bit 推理栈、同一提示词、同一图像预算、同一生成参数和同一 250 条 manifest。四个运行均完成 250/250 条预测。

| 模型 | 严格正确 | 严格准确率 | 相对原模型 | 宽松正确 | 宽松准确率 | 相对原模型 |
|---|---:|---:|---:|---:|---:|---:|
| 原始模型 | 164/250 | 65.6% | — | 193/250 | 77.2% | — |
| B1 | 164/250 | 65.6% | 0.0 pp | 195/250 | 78.0% | +0.8 pp |
| B2 | 165/250 | 66.0% | +0.4 pp | 197/250 | **78.8%** | **+1.6 pp** |
| B3 | 167/250 | **66.8%** | **+1.2 pp** | 195/250 | 78.0% | +0.8 pp |

B3 在严格指标上相对原模型改对 4 题、改错 1 题，净修复 3 题；B2 在宽松指标上净修复 4 题。

但是：

- B3 严格指标的两侧配对检验为 `p=0.375`；
- B2 宽松指标的两侧配对检验约为 `p=0.424`；
- 每个方案目前只有一个训练随机种子。

因此，B3 的 +1.2 个百分点是探索性差异，不是已经证明的稳定提升。

## 8. 当前实验结论

当前证据允许得出以下结论：

1. 本地 8 GB GPU 可以完成 Qwen2.5-VL-3B 的 NF4 QLoRA、检查点恢复和固定验证评测。
2. Answer-only SFT、Adapter 注入、梯度边界和保存加载链路均已通过实际训练验证。
3. 在有限数据下，把 LoRA 从语言注意力扩大到 FFN 没有形成明确优势，并增加了参数和推理开销。
4. 较低学习率的 B3 比高学习率方案更少破坏原始能力，在 val250 严格指标上获得当前最高的探索性结果。
5. val50 与 val250 的模型排序不同，证明数据代表性和评测协议会直接影响实验结论。
6. 当前还不能声称“QLoRA 稳定提升 ChartQA 1.2 个百分点”，也不能把 B3 作为已经确定的最终模型。

现阶段可以准确地介绍为：

> 基于 Qwen2.5-VL-3B-Instruct 构建消费级 GPU 可运行的图表问答后训练系统，实现 Answer-only QLoRA、语言模块级消融、可恢复训练、ChartQA 数据泄漏与分布审计，以及固定分层验证集上的逐样本可信评测。当前低学习率 Attention QLoRA 在单次 val250 实验中获得 +1.2 个百分点的探索性严格准确率差异，但尚需多随机种子复现，未作为最终能力提升结论。

现阶段不能表述为：

- 自研或从零训练了一个 3B 多模态大模型；
- 已经实现多模态 RAG、Agent、DPO 或强化学习；
- QLoRA 已被证明稳定提升 ChartQA；
- 已经完成 query-conditioned visual token selection；
- 当前 250 条结果等同于完整 ChartQA 官方基准。
