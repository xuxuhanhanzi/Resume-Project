# ForgeLLM 实施计划清晰度审查与修订记录

> 审查日期：2026-08-09（Asia/Singapore）  
> 审查对象：ForgeLLM 当前主计划、Stage 0–6 子计划、交接摘要、实验记录与根目录长期能力地图  
> 结论：技术覆盖充分，但修订前存在执行口径不统一、阶段验收不可一眼判定、状态冲突和长期地图/当前路线混淆。上述问题已在文档层修复。

## 1. 审查标准

每个阶段必须明确回答以下问题，缺一项就不能视为完整实施计划：

1. 为什么做：阶段目标与明确不做事项；
2. 何时开始：前置 Gate、冻结输入和资源条件；
3. 怎么做：有顺序的 Smoke → Quick Run → 正式运行 → 验收步骤；
4. 做出什么：代码、配置、Artifact、原始日志、报告和学习材料；
5. 怎样算完成：指标口径、分母、阈值、统计方法和负责人；
6. 失败怎么办：立即停止条件、允许调整项、缩小复现和后续决策；
7. 能声称什么：实现、实验和能力三个层级的结论边界；
8. 当前做到哪：自动化门与学习者门分开记录，且跨文档一致。

## 3. 分阶段审查

### Stage 0：路线切换

- **原有优点：** 目标、假设、质量门和失败处理已有定义。
- **原有不足：** 主计划中没有把“只证明路线切换，不证明模型能力”作为显式结论边界。
- **修复结果：** 补齐输入、执行顺序、必须产物、通过含义和冲突失败条件。S0 当前为通过。

### Stage 1：数据最低闭环与 Tokenizer

- **原有优点：** BPE/Unigram/现代方法范围、指标名称和工程证据完整。
- **原有不足：** 指标多但关键阈值未集中；子计划顶部写“学习者验收完成”，清单却仍未勾选。
- **修复结果：** 固定 round-trip 100%、byte BPE 普通文本 unknown rate=0、同输入同哈希和特殊 Token 契约；补齐执行顺序与失败分支；学习者门状态改为完成。G1 当前为通过。
- **结论边界：** 仍未证明 Picky/SuperBPE 等方法对真实语言模型有下游收益。

### Stage 2：Transformer、现代架构与模型系统

- **原有优点：** G2-Core/Arch/Systems 分层合理，正确性与平台边界已有大量证据。
- **原有不足：** 主计划没有集中写明前置冻结、执行顺序和核心数值容差。
- **修复结果：** 明确 G1 前置、5.36M 调试模型、三线执行顺序，以及 manual/SDPA 前向和梯度容差；规定 Core 失败时禁止 Stage 3 长训练。G2 当前为通过。
- **结论边界：** 教学 reference 不等于官方大模型复现；Windows 图捕获不等于 Inductor 性能证明。

### Stage 3：预训练闭环

- **原有优点：** 数据、Checkpoint schema、Resume、预算和实验记录最为完整。
- **原有不足：** 子计划仍标记“学习者验收待完成”，与交接摘要及主计划冲突；正式运行与退出条件分散。
- **修复结果：** 明确冻结输入、七步执行链、CPU exact-resume 状态集合，以及 1M target tokens/3600 秒先到即停；状态更新为 G3 已关闭。
- **结论边界：** 只证明小模型预训练闭环，不证明生产模型质量、长训练或大规模扩展。

### Stage 4：监督式后训练

- **原有优点：** 数据/模型 revision、LoRA/QLoRA 协议、预算和退化审计清楚。
- **原有不足：** 主计划未把目标行为不提升时的状态写成正式分支；子计划完成定义仍有三项未勾选。
- **修复结果：** 集中写明 mask/loss 100% 对齐、Base byte-exact、FP32 merge/unmerge ≤1e-6、正式短跑停止条件和 OOM 允许调整项；学习者门改为完成。
- **当前判断：** G4 工程与学习者门通过；strict generation 0/16，行为未达标，不能声称 SFT 能力提升。

### Stage 5：偏好优化与在线 RL

- **原有优点：** 双轨实验、数据与 reward 分离、前沿方法边界和停止条件较完整。
- **原有不足：** 学习者状态与交接冲突；已批准决策仍写作待讨论；pair 指标改善容易被误读为对齐成功。
- **修复结果：** 明确 DPO `atol=1e-6, rtol=1e-6` 对照、toy policy 改善、首步 on-policy 不变量、Base/Reference 无梯度和停止分支；G5-L 改为完成；决策改为归档。
- **当前判断：** G5 工程与学习者门通过；strict generation 未改善且回退存在，能力收益未证明。

### Stage 6：综合评测与最终验收

- **原有优点：** 身份冻结、污染审计、统计区间、盲评、系统矩阵和 claim 审计均已设计并实施。
- **原有不足：** “自动化完成”和“最终验收完成”的差别不够突出；行为门结果没有在主计划顶部直接暴露。
- **修复结果：** 分离自动化通过条件、学习者通过条件和行为通过条件；明确 30 对盲评、统计手算、调用链追踪和答辩为 G6-L 必做项；固定失败版本新目录规则。
- **当前判断：** G6-A～G6-E 通过；G6-L 待完成；Q0/Q1/Q2 strict 0/32 且截断率 1.0，模型行为 rejected。

### Buffer / Final

- **原有不足：** 只写“补弱与作品集”，没有明确禁止范围扩张，也没有可验收产物。
- **修复结果：** 增加启动条件、Release/复现命令/证据索引/claim 清单、陌生环境复现门和“未证明能力明确排除”要求。
- **当前状态：** 未开始；必须等 G6-L 关闭后启动。
